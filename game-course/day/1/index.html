Day 1 of 30Free lesson

Set up Roblox Studio and Claude Code

Install both tools, point Claude Code at a real Studio project, and make a script you did not type change something you can see.

Lesson video — recording in progress

Today's build task

Claude Code writes a script that turns a part a different colour when a player touches it. You run it in Studio and watch it work.

What today is actually for

Day 1 has one job: prove the loop works. Not the game loop — the work loop. You write an instruction in one window, and something changes in another window without you touching it. Everything in the next twenty-nine days is that same motion repeated at larger and larger scale, so it is worth half an hour to confirm it works on your machine before you depend on it.

Budget forty minutes. Most of it is downloads.

Install Roblox Studio

Studio is free and runs on Windows 10 or later and macOS 11 or later. Get it from create.roblox.com — you sign in with a Roblox account, and if you don't have one, make it now with an email you'll still have in a month. You will publish from this account on Day 28, so don't use a throwaway.

  1. Sign in at create.roblox.com and download Studio.
  2. Open it and create a new place from the Baseplate template. Not Classic Baseplate, not Village — the plain one, because an empty world is easier to see changes in.
  3. Save it locally as day1.rbxl somewhere you'll find it again.

If Studio won't launch on macOS, it is almost always Gatekeeper: open System Settings, go to Privacy & Security, and allow the Roblox app explicitly. On Windows, the usual culprit is an antivirus tool quarantining the installer mid-download.

Install Claude Code

Claude Code is a terminal tool. If you have Node 18 or later:

npm install -g @anthropic-ai/claude-code
claude

The first run walks you through signing in. You need a Claude subscription or API credit — this is the one unavoidable cost of the course beyond your own time.

Make a folder for the game and start Claude Code inside it. Keep this separate from where you saved the .rbxl file for now; on Day 2 you'll connect the two properly with Rojo, and it's clearer if you can see them as separate things first.

mkdir ~/roblox-30-days
cd ~/roblox-30-days
claude

The first instruction

Here's the part that matters. In Claude Code, ask for this:

Write a Roblox Luau script that makes a part change to a random
colour every time a player touches it. Put it in a file called
TouchColour.server.lua and explain which Studio container it
belongs in and why.

You will get back something close to this, plus an explanation:

local part = script.Parent

local debounce = false

part.Touched:Connect(function(hit)
	local character = hit.Parent
	local humanoid = character and character:FindFirstChildOfClass("Humanoid")
	if not humanoid or debounce then
		return
	end

	debounce = true
	part.Color = Color3.fromRGB(
		math.random(0, 255),
		math.random(0, 255),
		math.random(0, 255)
	)
	task.wait(0.2)
	debounce = false
end)

Now put it in Studio by hand, this once. Insert a Part into the Workspace, anchor it so it doesn't fall, add a Script inside the part, and paste the code in. Press Play. Walk your avatar into the part. It changes colour.

That is the loop, proven. From Day 2 onward you will never paste code by hand again — Rojo will sync it — but today you want to have seen both halves with your own eyes so that when the pipeline breaks later you know what each end is supposed to look like.

Three things worth noticing

Read what the agent wrote, because three details in it will come back repeatedly:

  • The debounce. Touched fires many times per second while a body part is in contact — once per limb, sometimes dozens of times for a single step. Nearly every "my script ran 40 times" bug in Roblox is a missing debounce.
  • The Humanoid check. Touched fires for anything that touches the part, including other parts falling on it. Checking for a Humanoid is how you ask "was that actually a player?"
  • The .server.lua suffix. That tells Rojo, on Day 2, that this code runs on the server and not on the player's machine. Getting that distinction wrong is the single most common source of both broken features and exploitable games, and all of Day 4 and Day 12 are about it.

Ask Claude Code to explain any of those in more depth right now if you want. Using the agent as a tutor on the code it just wrote is a habit worth forming on Day 1 — it is faster than searching, and it is grounded in the exact code in front of you.

Ask a second question

Before you close the terminal, try one thing that fails interestingly:

What happens to this script if a player rejoins the game?
Does the colour persist? Why or why not?

The answer is no, and the reason — nothing is stored anywhere outside the running server — is the entire premise of Day 13 on DataStores. You are not fixing it today. You are building the instinct to ask "and what happens when…" before the agent has to be told.

Done when

  • Roblox Studio opens a Baseplate place and you can press Play and walk around.
  • Claude Code runs in a project folder and answers you.
  • A part in your place changes colour when your avatar touches it, from code you did not write.
  • You can say out loud why the debounce is there.

Tomorrow: Rojo and Git, so your code lives in real files under version control instead of trapped in a binary .rbxl — which is the thing that makes an agent crew possible at all.
